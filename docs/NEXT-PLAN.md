## 四、方法论约定（本轮血泪教训）

### 排查准则
1. **先确认代码有没有执行**，再怀疑逻辑对不对
2. 用**文件写入**做诊断（DSH 日志拿不到），不用 console
3. 诊断覆盖**完整路径**：入口 → 分支 → 出口
4. 修「显示值」时，先查**这个值从哪来、还有哪些路径会写它**

### 三层数据模型（必须同时同步）
```
磁盘文件  ledger.json
    ↕ (2 秒防抖 flush 覆盖)
内存实例  QuotaLedger.data
    ↕ (5 秒节流)
进程缓存  balanceLogCache / ownLedgerCache / creditPriceCache
    ↕
显示层    弹窗 / 账单 / 详情
```
**任何跨层写操作，都必须同步所有层。** 否则会被另一层覆盖。

### 禁止事项
- ❌ 没有诊断就改公式（会像 ¥0.00 那样改 12 轮无效）
- ❌ 只改显示路径、不改写入路径（会导致重算被覆盖）
- ❌ 用 `catch (e) {}` 吞掉未知异常（会掩盖 ReferenceError 这类致命错误）

## 已解决的关键问题（7.10 ~ 7.12 系列）

### 面板点数据格消失（12 轮排查）
**根因**：`ProviderTable` 里误用 `c.modelCacheHit`（应为 `r`），
点击渠道行展开时抛 `ReferenceError`，React 卸载子树。

**教训**：
1. **错误边界是必需品**，不是可选装饰 —— 没有它，崩溃表现为「静默消失」
2. **坐标探针比猜测有效**：`tag=TD pt=554,519 el=429,501 144x31` 直接证明事件没错位
3. 排查顺序：先确认「代码有没有跑」→ 再看「跑得对不对」→ 最后才怀疑架构

### 其他已修
- 双实例 state 不同步（7.11.1）
- DSH slot 每 700ms 重建组件 → UI 状态提升到模块级（7.11.8）
- 积分轮询闭包冻结 → ref（7.11.5）
- 轮询 effect 依赖 `data` → 定时器被反复重置（7.11.7）

## 搁置项（用户 2026-11-17 决定）

### S-1 小鲸鱼气泡币种刷新「差一档」

**现象**：切币种后点小鲸鱼，显示的是**上一个币种**的值；必须等消耗泡泡自然结束（或手动关闭）后再点一次才正确。

**已试方案（7.18.0 → 7.18.3，4 版未成）**：
| 版本 | 尝试 | 结果 |
|---|---|---|
| 7.18.0 | POST /config 返回 money | 汇率实时了，气泡没变 |
| 7.18.1 | 币种变化时绕过 costBubbleActive 写金额行 | 无效 |
| 7.18.2 | else 分支无条件写金额行 | 无效 |
| 7.18.3 | whaleClick 开头加 refresh(true) + 后端 refresh=1 清缓存 | 无效 |

**服务端已确认正确**（实测三次切换）：
```
CNY: 8.49 / CNY    USD: 1.2735 / USD    EUR: 1.1563 / EUR
```

**剩余疑点**：
- `whaleClick` 的 `refresh(true)` 是异步的，数据回来时泡泡可能已关闭或已定格
- `render()` 的 `costBubbleActive` 早退可能在其他路径（`applyBubbleLines` / `setHint` 的淡入动画）复活
- `bubbleScene.kind === 'cost'` 时 `showBubble()` 也早退，可能整条更新链被切断

**下次排查建议**：
1. 在 `whaleClick` 与 `refresh` 回调里都打 `console.log`（已有 `[dsh-whale] 更新` 探针），先确认「点击后 refresh 是否真的执行」
2. 若执行了但界面不变，在 `amountEl.textContent` 赋值前后打印旧/新值，确认是否被后续代码覆盖
3. 考虑放弃「泡泡期间不重绘」这个优化，改为**只对币种变化强制重绘**

**影响**：仅「切换币种后首点显示旧值」，点第二次即正确。**不影响数据正确性**（服务端和账本都是对的）。

- 命令行安装（pnpm add）依然有效，且已验证

## 自动更新方案讨论（2026-11-18）

### 用户意向

### 方案对比
| 方案 | 优点 | 缺点 |
|---|---|---|
| GitHub Releases + 更新脚本 | 标准、可追溯、支持版本对比 | 需要建仓库 / 上传 release 资产 |
| 坚果云共享包 + 更新脚本 | 双机场景简单、无外网依赖 | 需要手动上传新包 |

| DSH 插件 UI 手动更新 | 最简单 | 每次手动操作 |

### 推荐
**GitHub Releases + PowerShell 更新脚本** 或 **坚果云共享包 + 更新脚本**。

## DSH 插件更新机制调研（2026-11-18）

### 用户疑问
> 是不是可以在插件列表中检查更新？

### 调研结果
DSH 官方插件列表**没有内置「检查更新」功能**（只有启用/禁用/添加插件）。

社区有第三方更新插件：
- Plugin Upgrader: https://dshpluginhub.ai/plugins/happyqu-dsh-plugin-upgrader
- dsh-plugin-updater: https://dshhub.org/zh-CN/plugins/YukiSuoug/dsh-plugin-updater

**结论**：
- 官方无更新检查
- 第三方 updater 可调研，但依赖其兼容性（是否支持本地 tgz / 自定义源）
- 自研 update.ps1 仍是最可靠的方案

### 后续可考虑
若第三方 updater 支持自定义 GitHub 源，可替代自研脚本。
